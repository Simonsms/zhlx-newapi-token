# 管理端数据筛查标准

版本：2026-10-30（含二期场景分类）。适用对象：采集管理端（`/_zhlx/admin`）及其管理 API。本文回答一个问题：**哪些数据能被筛出来、按什么口径、筛不出来的有哪些**。

## 1. 数据来源与覆盖范围

管理端的数据来自两个独立数据集，按部署 ID（`DEPLOYMENT_ID`）隔离：

| 数据集 | 内容 | 覆盖范围 |
| --- | --- | --- |
| 用量镜像（usage_event） | 从 New API 原生日志同步的消费、错误、退款事件 | **全量**推理调用，与是否采到正文无关 |
| 采集请求（proxy_request） | 经过采集代理的推理请求元数据、脱敏正文与分类结果 | 仅**经过代理入口（50085）**的请求 |

关键口径：**用量统计是全量的，正文只是子集。**没有正文的调用照样计入用量；正文覆盖率单独展示，不能反推"没采到 = 没人用"。

## 2. 可用筛选维度

### 2.1 时间范围

- 参数：`from` / `to`（ISO 时间）。默认最近 24 小时。
- 上限：单次查询跨度不超过 **366 天**，超出报 `range_too_large`。

### 2.2 身份维度

| 筛选项 | 依据 | 说明 |
| --- | --- | --- |
| 账号 ID（user_id） | 原生日志 | 一人一账号时即个人；共享账号时恒为同一值 |
| 凭证 ID（token_id） | 原生日志 | 共享账号下区分人员的最小单位 |
| 人员归属口径 | `IDENTITY_MODE` | `auto`：仅一个账号且多个凭证时按凭证；`user`：按账号；`token`：按凭证。管理页显示当前生效口径 |

限制：身份完全依赖原生日志，**不信任客户端自填的用户头**；共享凭证只能归到凭证层，无法定位到自然人；共享 Key 若被多人使用，只能看到凭证级用量。

### 2.3 模型与关联状态

- 模型：精确匹配（区分大小写按库内存储值）。
- 关联状态：`matched`（已匹配原生日志）/ `pending`（等待日志，窗口内）/ `unmatched`（超窗未匹配）/ `no_gateway_id`（上游未返回网关请求 ID）。默认窗口 300 秒，可配置。

### 2.4 正文关键字

- 参数：`q`，对**已保存的脱敏正文**做不区分大小写的子串匹配。
- 只匹配保存下来的文本：头尾节选的中间部分**搜不到**；仅元数据记录（附件、工具结果、无文本）没有正文，关键字筛不中。
- 不支持正则、通配符与全文索引；按当前数据量（数万条）子串扫描可接受，数据量显著增长后需评估。

### 2.5 场景分类（二期新增）

- 参数：`label`，精确匹配分类标签：`code_dev`（代码开发）、`doc_writing`（文档写作）、`knowledge_qa`（知识问答）、`data_analysis`（数据分析）、`translation`（翻译润色）、`other`（其他）。
- 仅对有正文且已分类的记录生效；分类状态、版本、置信度可查但不可直接作为筛选条件。
- 标签是模型/规则推断，**不是用户意图事实**；版本（`classifier-v1-*`）随每条记录保存，改规则后新旧口径不混用。

### 2.6 分组与汇总

- 用量分组：`identity`（按人员自动口径）/ `day` / `user` / `token` / `model`。
- 用量指标：消费/错误/退款事件数、输入/输出 Token、网关额度。Token 缺失记为 null 并计入 `missing_events`，**不按零处理**；本地估算单独计入 `estimated_events`；额度是网关结算值，**不是供应商现金成本**。
- 分类凭证排除：`EXCLUDE_TOKEN_IDS` 中的凭证（如分类服务专用 Key）不计入按人员/凭证的分组，避免污染人员统计；全量总量仍包含。

## 3. 单条记录可见字段

列表：时间、接口、模型、正文结果（已采集文本/已截断/仅元数据/资源受限/采集故障/采集关闭/已过期 + 原始 `skip_reason`）、关联状态、Prompt 入口、网关请求 ID。

详情额外可见：

- 脱敏正文全文（含节选标记）、提取范围（如 `responses_input`、`last_user_message`、`+excerpt`）、提取与脱敏版本、截断标记。
- 实际观察请求体字节数与读取完整标记（不含 HTTP 头，不等于 Token）。
- 内容概要：附件类型/数量、是否含工具结果、未知块类型、附件声明大小（仅协议中可见的有限信息）。
- 关联的原生消费事件：类型、时间、账号/凭证、输入/输出 Token、额度、用量来源（reported/estimated/missing）。
- 分类结果：标签、分类器版本、置信度、是否待复核、分类时间。
- 传输终态（completed/client_cancel/upstream_error/timeout/proxy_error/no_response）与耗时。

**正文读取写审计**（admin_audit），非管理员一律 401，篡改会话无效。

## 4. 筛不出来的数据（明确边界）

| 数据 | 原因 |
| --- | --- |
| 回答正文、assistant/system 消息、工具定义 | 设计上不采集 |
| 图片/PDF/音频等内容本身 | 只记类型、数量与声明大小，不下载不解码 |
| 文件 ID、签名 URL、完整本地路径 | 脱敏规则移除，不入库 |
| 已过期的正文（默认保留 30 天） | 保留期到后置空并标记 `expired`，元数据仍在 |
| 未经代理的调用 | 客户端绕过 50085 直连后端时，无采集记录（后端仅回环监听，正常配置下不存在） |
| 网页访问、静态资源、健康检查 | 不属于推理请求，不记录 |
| 一次调用的"真实人工提问次数" | 无可信轮次标识；多轮历史重传与 Agent 自动调用无法区分 |
| 生产力、采纳率、任务完成 | 需要业务侧事件，网关数据无法推断 |
| 跨部署数据 | 按部署 ID 隔离，不跨库关联 |
| 导出文件（CSV/Excel） | 管理端暂未提供导出，仅在线查询 |

## 5. 数据质量与可信度

- 每条记录带提取/脱敏/分类版本，历史记录按原含义展示，不批量重写。
- 「正文结果分布」明确分母：进入采集范围的推理请求；主动省略（附件/工具/无文本）、资源受限（超限/预算）、系统故障（解析/脱敏失败）分开计数。
- 同步水位、上次成功时间、最近错误可见；同步失败不推进水位，恢复后自动回补。
- 去重按稳定源事件键：重复拉取、重叠窗口不重复计数；同一请求多条日志按类型分别保留。
- 未匹配/缺失保留状态，不填零、不内连接丢弃。

## 6. 管理 API 一览

| 端点 | 用途 |
| --- | --- |
| `GET /_zhlx/admin/api/overview` | 总量、身份口径、采集质量、关联计数、用量来源、同步状态 |
| `GET /_zhlx/admin/api/usage?group_by=` | 用量分组（identity/day/user/token/model），支持 user_id/token_id/model 筛选 |
| `GET /_zhlx/admin/api/requests` | 请求列表，支持 from/to/user_id/token_id/model/status/label/q/page/page_size |
| `GET /_zhlx/admin/api/requests/{id}` | 单条详情 + 关联用量事件（写审计） |
| `GET /_zhlx/admin/api/capture-quality` | 正文结果分布、跳过原因、请求体字节计量、提取版本分布 |
| `GET /_zhlx/admin/api/classification` | 分类覆盖率、标签分布、待分类/失败/待复核计数、分类器版本 |
| `GET /_zhlx/admin/api/sync` | 同步水位与状态 |

所有端点需要管理员会话；未配置 `ADMIN_API_TOKEN` 时返回 503。
