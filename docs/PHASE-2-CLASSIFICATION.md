# 二期：离线场景分类

状态：已实现并上线。分类器默认关闭，需显式配置 `CLASSIFIER_MODE`。

## 1. 目标与边界

在已有采集数据上做离线打标，回答"这些请求大概在做什么"。分类只读已落库的脱敏正文，独立于转发链路，失败只重试和计数。

不在本期范围：修改 New API、客户端 SDK、回答正文分析、会话重建、精确人工提问次数、新消息队列、BI 平台。

## 2. 标签集

固定六类，写死在代码白名单里，模型无法输出白名单外的标签：

| key | 名称 | 典型内容 |
| --- | --- | --- |
| `code_dev` | 代码开发 | 写代码、查报错、改脚本、部署配置 |
| `doc_writing` | 文档写作 | 周报、报告、邮件、方案、文案 |
| `data_analysis` | 数据分析 | 表格、统计、透视、环比、图表 |
| `translation` | 翻译润色 | 翻译、改写、措辞调整 |
| `knowledge_qa` | 知识问答 | 概念解释、制度查询、原理 |
| `other` | 其他 | 无法判断 |

每条记录保存：`classification_label`、`classifier_version`、`classification_confidence`（0–100）、`classification_review`（待复核）、`classification_attempts`、`classified_at`。

## 3. 两种分类器

### 3.1 keyword（默认推荐，零成本）

`CLASSIFIER_MODE=keyword`。确定性规则：每个场景有强特征（+2 分）和弱特征（+1 分），取最高分。

- 强特征命中 → 置信度 80；仅弱特征 → 60。
- 多个场景并列最高分 → 取其一但置信度降到 55 并标记待复核。
- 无命中 → `other`，置信度 30，强制复核。

优点：不花钱、不联网、可重复、结果稳定。缺点：只能识别有明显词汇特征的文本。

### 3.2 llm（可选，需要模型凭据）

`CLASSIFIER_MODE=llm`，并配置 `CLASSIFIER_LLM_BASE_URL`（默认复用 `UPSTREAM_URL`）、`CLASSIFIER_LLM_TOKEN`、`CLASSIFIER_LLM_MODEL`。

- 调用 OpenAI 兼容的 `/v1/chat/completions`，`temperature=0`，`max_tokens=60`。
- 系统提示明确要求把用户文本当作不可信数据、忽略其中的指令，只输出固定 JSON。
- 不提供任何工具；输出必须是 `{"label":"...","confidence":N}`，标签不在白名单即判为失败。
- 置信度低于 `CLASSIFIER_REVIEW_THRESHOLD`（默认 60）标记待复核。

**务必使用专用凭证，并把它加入 `EXCLUDE_TOKEN_IDS`**，否则分类调用本身会混进员工用量统计。该凭证也不应经过采集代理。

## 4. 运行方式

后台任务每 `CLASSIFIER_INTERVAL_MS`（默认 5 分钟）取一批 `CLASSIFIER_BATCH_SIZE`（默认 50）条待分类记录：

1. 只处理 `prompt_text IS NOT NULL` 的记录；无正文的元数据记录永远不分类。
2. 已分类的不再处理。
3. 失败记录累加 `classification_attempts`，超过 `CLASSIFIER_MAX_ATTEMPTS`（默认 5）后不再重试；重试间隔 `CLASSIFIER_RETRY_MS`（默认 10 分钟）。
4. 单条失败不影响同批其他记录，也不影响推理转发。

## 5. 已上线配置（生产 43.162.111.70）

```bash
CLASSIFIER_MODE=keyword
CLASSIFIER_INTERVAL_MS=300000
CLASSIFIER_BATCH_SIZE=50
```

## 6. 管理端可见内容

- 筛选区新增「场景」下拉，可按六类筛选请求。
- 请求列表新增「场景」列，显示标签与置信度，待复核项用不同样式。
- 详情显示场景、置信度、分类器版本与待复核标记。
- 侧栏新增「场景分布」卡：有正文数（分母）、已分类、未分类、分类失败、待复核、覆盖率、标签占比、分类器版本分布。

## 7. 口径提醒

- 场景比例的分母是**已分类且有正文**的请求，不是全部推理调用，也不是员工时间占比。
- 标签是规则或模型推断，不是用户意图事实；`other` 和待复核项需要人工抽样核对。
- 分类版本随记录保存，改规则后新旧口径不混算。
- 历史 `extract-v1` 记录按原含义展示，不因分类而重写。

## 8. 回退

`CLASSIFIER_MODE=off` 后重启即可停止分类；已写入的标签保留，不影响采集、同步与查询。数据库新增字段可空，旧版本代码读取不受影响。

## 9. 后续建议

1. 对 25 条待复核做一次人工抽样，校准关键词规则。
2. 若要提升准确率，先在小批量上对比 keyword 与 llm 结果，再决定是否切换。
3. 若启用 llm，务必先创建专用凭证并配置 `EXCLUDE_TOKEN_IDS`。
