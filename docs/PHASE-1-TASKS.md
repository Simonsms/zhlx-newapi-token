# 第一阶段任务：New API Prompt 采集、用户与 Token 关联、管理员查询

实现状态：四个任务均已落地于本仓库，验收对照见 [ACCEPTANCE.md](ACCEPTANCE.md)。离线分类属于第二阶段。

父需求：[PRD](./PRD.md)。每个任务都包含可演示的入口、存储、管理员读取和行为验收，不把独立数据库层或前端层拆成无成果的横向任务。

## 任务一：原 Key 透传与管理员请求状态查询

类型：AFK（试点部署前的入口切换审批另见上线门槛）  
Blocked by：None，可立即开始。  
覆盖用户故事：1、2、8、13。

### What to build

建立轻量采集服务的最小链路：客户端通过代理使用原 Key 调 New API，代理记录本地请求 ID、可观察的网关请求 ID、时间、接口与传输终态，并提供仅管理员可访问的请求状态列表。第一条切片只采元数据，默认关闭正文采集；部署边界阻止绕过受控入口的路径由试点环境验证。

### Acceptance criteria

- [ ] 普通请求与 SSE 分块、慢客户端、取消、超时及上游错误保持原转发行为，代理不自动重放推理 POST，分析库故障不阻断转发。
- [ ] 原 Key 透传、不落库、不进异常日志；代理读取响应头 `X-Oneapi-Request-Id`，无响应头记 `no_gateway_id`，不能把自填用户头当身份。
- [ ] 管理员按日期／请求 ID 查看元数据和传输终态；非管理员或未认证请求在服务端被拒；关闭正文采集时各持久副本均无正文。
- [ ] 测试覆盖 SSE 拆包、取消传播、失效 Key、分析队列满、无网关 ID 和查询越权，并记录失败与丢弃计数。

## 任务二：全量原生日志同步与管理员用量报表

类型：AFK（真实日志源接入与授权需运维配置）  
Blocked by：任务一（复用管理鉴权和请求展示）。  
覆盖用户故事：3、4、7、9、14。

### What to build

从 New API 的只读日志库或受控管理员日志 API 增量同步全量消费事件，不限于已经采集正文的请求；保存日志类型、可信用户／凭证归属、模型、输入／输出 Token、用量来源与网关额度。管理员可按日期、用户和模型查看用量与同步覆盖状态。

### Acceptance criteria

- [ ] 按实际后端核验稳定源事件键；固定结束时间和重叠回补窗口重跑不重复入账，不以用户 API 的展示 ID 作通用游标，也不以请求 ID 单独去重不同事件。
- [ ] 报表统计全量原生消费记录；调用数、消费事件数分口径展示，输入／输出 Token 不重复叠加缓存／推理子项，quota 标为网关额度而非供应商成本。
- [ ] 原生估算与缺失分别标记；缺失 Token 为 null，不以零代替；两个人的独立凭证不串人，共享 Key 不显示为已识别真人。
- [ ] 管理员可筛日期、用户、模型并查看同步水位／错误与回补结果；未授权读取被拒；重复、迟到、退款／错误日志及源端缺失测试通过。

## 任务三：受控 Prompt 采集与管理员脱敏正文检索

类型：AFK（真实用户正文启用需安全／业务负责人核准用途与期限）  
Blocked by：任务一。  
覆盖用户故事：5、10、11、12、13。

### What to build

在已确认的接口范围和统一采集开关下，从客户端请求中提取有界的获准 user 文本副本，脱敏后异步写入独立采集请求表；管理员可查询脱敏正文、采集状态和跳过原因。原请求字节不因采集而改变；不保存回答正文。

### Acceptance criteria

- [ ] 默认关闭正文；启用范围、提取协议和版本明确，超大媒体、未知格式、过大文本、非成功响应及脱敏失败只留必要元数据与原因，不记录原文。
- [ ] 分析副本在首次持久化前去除 Key、Authorization、Cookie 和常见敏感实体；队列满或库故障不阻断推理，并显示丢弃计数；入口临时文件与异常日志也经核查。
- [ ] 管理员按日期／采集状态／请求 ID 检索正文；非管理员的列表与详情均拒绝；查询和导出（若本期提供）有读取审计，过期正文不可读取。
- [ ] 测试覆盖敏感样本、开关、大小上限、脱敏失败、并发相同 Prompt、流式与采集故障；重传历史文本不得被标成已确认的“本轮新增输入”。

## 任务四：逐请求关联与管理员联合查询

类型：AFK。  
Blocked by：任务二、任务三。  
覆盖用户故事：5、6、7、8、9。

### What to build

在同一部署内按网关请求 ID 联结代理请求和原生日志；管理员从用户／模型／日期用量列表进入单次请求，查看可信用户与凭证、脱敏 Prompt、消费事件及 Token，同时查看 pending、matched、unmatched 的关联状态与质量指标。

### Acceptance criteria

- [ ] 同一请求的多条源日志逐条去重、按类型处理，不因重复同步而重复累计 Prompt 或用量；未关联记录保留，缺失用量不填零。
- [ ] 一个网关请求 ID 不跨部署关联；并发的相同 Prompt 按本地请求 ID 分开，冲突身份事件不自动归属给某个人。
- [ ] 管理员能从报表筛选下钻到请求详情，查看来源与状态、Prompt 采集覆盖／丢弃／未匹配数；无正文的调用仍保留在全量用量统计中。
- [ ] 通过日志延迟、重复、缺失、取消、源日志多事件及共享 Key 的端到端回放，核对总量与子集，验证非管理员无法读取详情。

## 上线门槛与第二阶段边界

试点启用前须由使用方核验实际 New API 版本、日志后端及开关、账号与 Key 分配（尤其共享 Key）、管理员认证来源、入口绕过路径、正文采集用途、告知和具体保留期。这些属于待确认的运行条件，不把资料中的假设视为现状；未确认前任务三仅能用测试凭证与合成文本验证。

第二阶段另行拆任务：离线分类、固定标签与版本、抽样复核、分类覆盖率及场景趋势。分类任务不得反向进入采集代理，分类调用用量与员工统计分开；第一阶段不交付任何分类界面或指标。
